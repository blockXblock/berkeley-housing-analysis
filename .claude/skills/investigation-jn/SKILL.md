# Investigation-JN convention
(Moved from CLAUDE.md "Discipline (every session)" 2026-09-29. The general principle
"Anchor checks to what stays true" stays in CLAUDE.md — it applies to every gate, not only JNs.)

- **Investigation-JN convention** — an investigation that sprawls across many scratch `.py` files **consolidates into a committed JN** (a `build_jn_*.py` generator → `notebooks/v4/JN-*.ipynb`, markdown-in-source) as its durable, re-runnable home. Structure each section **markdown (assumption + plan + why) → code (the operation) → markdown (found + verify)**; the **text cells are the deliverable** (they capture the assumptions that otherwise live only in audit prose + chat). The exemplar is **JN-E** (`scripts/v4/build_jn_e.py`, the CO reconciliation).
  - **DERIVE + compare-to-baseline, NEVER hardcode the answer.** A reproducible JN **derives** every result figure from the data, then **asserts derived == an EXTERNAL TIMESTAMPED BASELINE FILE** (`data/baselines/<topic>_baseline_<date>.json`, carrying the `v4_sha` + per-figure provenance) — **never against hardcoded constants in the logic**. A gate mismatch must **DIAGNOSE** (computed vs baseline, sha then/now, likely cause) and HALT, both ways (prove it like JN-A's anchor test). **A legitimate result change = APPEND a new timestamped baseline (EVIDENCE-append-only), never a hand-edit of a magic number.** *Why:* a notebook that hardcodes the answer it computes isn't reproducible (it has the answer key baked in) and forces manual surgery when the data legitimately changes; derive-and-compare keeps the logic pure, makes drift diagnosable, and records the result's checkpoint history.
  - **Visualization in investigation JNs:** every JN includes viz cells serving TWO goals — **(1) VISUALIZE THE SUBJECT**: quantitative charts for quantitative data (waterfall, bar, distribution), flow/Sankey for data that moves through stages, structural diagrams for qualitative/decision logic; **(2) DIAGRAM THE DATA FLOW**: a lineage/branching diagram showing sources → transforms → destinations (which raw file → which JN → which table → this result), making the data's provenance VISIBLE.
    - **Stack:** **plotly** (interactive quantitative charts + Sankey for flow volumes — hover/zoom, exports to HTML for curriculum/public use), **graphviz** and/or **mermaid** → SVG for lineage and flow diagrams (mermaid renders in `.ipynb` on GitHub; graphviz for richer lineage). **Not pandas** — pandas manipulates, the viz layer renders on top. Start with static-but-interactive (high value, achievable); execution-driven animation is later polish, not required.
    - **CARDINAL RULE — derive, never hardcode** (same discipline as the gates): viz cells read DERIVED values or the baseline file, **NEVER literals typed into the chart call**. A hardcoded chart decays (shows the old number after the data changes). **The chart must change when the data changes.**
    - **TEXT-SANDWICH + viz-verifiability:** each viz cell is sandwiched in markdown — 📝 before (what it shows + what to read from it) → ▶ the viz (deriving from data) → 📝 after (**what it could MISLEAD about** — truncated axes, held-vs-counted, net-zero-shown-as-flow). A chart compresses and emphasizes, so it can overstate more easily than a number; the annotation guards against it. *Example:* a reconciliation Sankey must mark the **+147 as HELD** (dashed/distinct), not counted, or it implies a count we deliberately didn't make.
