## 1. Method (the thesis): primary-source-only ingest

The 96 Bucket-A CY2024 completions are projects the city reports complete but our
pipeline never ingested — and they sit in our **CPRA file already**.  We were only tracking >5 unit projects until we did a public data request. 

Built each
record from primary sources:

| field | source (primary) |
|---|---|
| APN join key | CPRA `Parcel Number` → `normalize_apn()` (strip non-digits) → `berkeley.db apn_norm` |
| coordinates | **Alameda assessor** (`berkeley.db parcels_full Latitude/Longitude`) |
| unit count | **CPRA Rule C (net-new):** `UnitsAdded` if present, else 1 for `ADU=Yes`, else `NumberUnits` |
| BP #, CO date, valuation, ADU flag, occupancy | **CPRA** (`PermitNumber`, `Finaled/Completed Date`, `JobValuation`, `ADU`, `OccType`) |

**CKAN was used ONLY to verify the result** (post-ingest 709 ≈ the city's clean
708), **never as a source.** The CY2024 count is now comprehensive *and*
primary-source-backed; CKAN remains the verification target.

## 3. Schema change

- **`unit_program.bedroom_count`: NOT NULL → nullable** via the SQLite 12-step
  table rebuild (create new table, copy 179 rows, drop, rename, recreate index
  `idx_unit_program_version`). The CHECK kept as
  `bedroom_count IS NULL OR BETWEEN 0 AND 10`.
- **`v_projects_flat` recreated PRESERVING the permit-fix subsidiary
  `NOT EXISTS` logic** (the two milestone subqueries). Verified intact: DB-level
  major CY2024 CO = **786**, not ~1233 — the permit fix survived the rebuild.
  `v_project_unit_mix` and `v_project_affordability` also recreated unchanged.
- **Income: no schema change** — used the pre-existing `vocabulary_income_categories
  UNKNOWN (id=6)`. This keeps the INNER-JOIN affordability views/queries working
  with ADU units **visible and labeled Unknown** (a nullable `income_category_id`
  would have silently dropped them from those INNER JOINs — confirmed).
- **The −1 sentinel is retired** — it violated `CHECK (bedroom_count BETWEEN 0
  AND 10)`, and `0` already means studio. NULL is the only honest unknown.

## 4. Honest unknowns (none assumed)

Every ADU fact row carries provenance (`source_document_id` → a CPRA document,
`asserted_by` = "CPRA + Alameda assessor", `confidence_type`). Fields primary
sources don't carry are stored as explicit unknowns, not guessed:
- `bedroom_count = NULL` (not in CPRA/assessor)
- `tenure_type_id = 8` (Unknown — "not yet determined from sources")
- `income_category_id = 6` (UNKNOWN)

**Pre-existing, NOT fixed here:** the 179 legacy `unit_program` rows all carry
`bedroom_count = 1` (a uniform placeholder from the v1→v2 migration, logged as
"placeholder" in `migrate_v1_to_v2.py`). Those are left as-is — a separate issue
from this ingest.
