### Multi-source reconciliation is a FEATURE (John's principle)
CPRA xlsx, Accela `.txt`, the building TSV, and inspection JSONs are **independent sources that cross-check each other**. Where ≥2 agree on a permit's BP/CO date, unit count, or description → high confidence. Where they **disagree → that's a finding** (city error / scrape error / real discrepancy), not noise to smooth over. D5's reconciliation cells should **surface disagreements**, never silently pick a winner. Having the same fact in spreadsheet + JSON + CSV + .txt is validation-by-triangulation, not wasteful duplication. For the HCD comparison specifically, "which sources corroborate this number" is itself reportable rigor the city's own APR lacks.

### One caution on the "cycle logic in a cell" point
The body says RHNA `bp_cycle`/projection-period scoping can live in a notebook cell (true — no materialized column required). But flag the stakes: **cycle scoping is load-bearing for the HCD comparison.** If the projection-period window is wrong, the A2 counts the wrong years and the HCD diff is silently apples-to-oranges. Whether it's a cell or a column, **validate it against `housing_rules`'s cited logic** (it carries statute citations), don't improvise the cycle boundaries. Cheap to wire; not cheap to get subtly wrong.
