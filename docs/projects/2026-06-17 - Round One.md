### The join: use S0's `matches()` relation, not string equality

v3 stores street cores without a type suffix (`<2650 TELEGRAPH>`); the oracle has it
(`<2650 TELEGRAPH AVE>`). The type tolerance lives in S0's `AddressKey.matches()` relation (bucket index +
type-wildcard), **not** a stored suffix. Joining with `matches()` recovered **357 buildings** a string-==
join would have falsely called "v3-only." Ambiguity guard (absent-type → >1 present-type) fired **0** times.
v3 is untouched — the fix was purely in the S9 comparison.

### The 2022 −260 drilled, then the join fully augmented

The −348 city-coverage rested on a bucket+`matches()` join that **systematically under-matches**. The 2022
−260, classified by APN **and** address against all v3 buildings, dissolved: **79u match-failure** (in v3,
join missed), **138u attribution** (v3 has them, different year — dominated by **2352 Shattuck 135u**), and
only **43u genuine coverage**. So the join was augmented: bucket+`matches()` first, then **APN-match the
residual** (canonical Option-B), union-find clustering to prevent double-matching.
