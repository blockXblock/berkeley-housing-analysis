## THE HEADLINE OPEN ISSUE — building identity (bigger than 2352 Shattuck)
- **Root cause (confirmed):** S1 (`build_s1.build_spine`) keys buildings by **address** `(number,street,stype)`,
  so it collapses genuine multi-building developments. `net_units=MAX` then keeps the largest permit's units;
  S2 picks one CO = MAX(finaled). NOT a parsing/APN-lookup bug — the APNs are found and stored; the *rule*
  merges by address.
- **2352 Shattuck / Logan Park (proj179, building 1037)** is the material case: v3 = **135u @ 2023** (a
  Frankenstein: North's units + North's BP + **South's** CO date). Truth = **North 135 @ 2022 + South 69 @
  2023 = 204**. The North's real CO (2022-01-14) is **absent from s2_events**. Visible in the ledger as
  +66 (2023 matched) and −135 (2022 city-coverage) — same building, both halves.
- **APN is NOT the fix.** Forensic (this session): **14** completed records fold ≥2 distinct New
  housing-creating permits into one — **12 are same-parcel** (main+ADU / duplex / cottage-court, e.g. `1446
  5TH` = 4 New 1u permits → v3 counts 1), only **2 cross-parcel**. One parcel routinely holds many buildings;
  one building can span many parcels (condos). So neither address nor APN is a valid building key.
- **The real fix = permit-based building identity** (a building = its own New master permit + its CO),
  re-keying S1 AND S2–S8 (all of which currently key by address and would re-merge any S1 split — the
  propagation blocker). Proposed as a scoped **"S1.5 building-identity from permits"** stage, gated like the
  rest. **Bounded impact** (~tens of units, partly offset by the +481 ADU over-finds), so it's an INFORMED
  FLAG, not yet built.
- **`scripts/build_v2/build_s1.py` carries the split rule WRITTEN but UNWIRED** (the call is commented out
  with a note). **Do NOT wire it without the S2–S8 re-key** — it would produce 1386 in S1 then re-merge in S2.
- Discrimination is the hard part: must tell 4-distinct-buildings (SUM) from phased-one-building (MAX, the
  reason MAX exists) from New+alterations (MAX). Needs description/permit-type logic, not a blind SUM.
